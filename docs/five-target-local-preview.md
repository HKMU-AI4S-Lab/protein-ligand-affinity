# Five-target Fusion screening: local preview record (28 September 2026)

## Scope and model contract

The local Screening workbench offers MAO-B (`aofb`), EGFR, PARP1, DPP4 and HIV-1 protease (`hivpr`). Each choice maps to a separate **full GridSmiMCANet/Fusion checkpoint**. The model receives 100 encoded SMILES characters and a 28 × 24³ grid made from a generated ligand conformer. The `protein` argument in the recovered forward method is unused. A protein sequence, structure, binding site or protein–ligand complex is not submitted to Fusion inference. The class-1 softmax is a relative target-specific screening score, not affinity, an experimental probability, or a number comparable between targets.

The original source is in `artifacts/research-source/fusion-aofb/`, recovered from HKMU `/home/dwanghkmu/kerongji/code/MCANet_Ablation`. `model.py` SHA-256 is `7e0be1a53a248357b00c536d262fceb68689ada6ab8494ef089987c0632520cd`; `utils/DataSetsFunction.py` is `bfa1b35395fc5d54af584ff989d05d1860712e9625ff5ba302a7e00849fe2a98`; `config.py` is `3b3ae053cfb637e87fe5c34cdafac2e731b38f0433360084bf1398552a37959e`. The recovered training entry points are preserved as `artifacts/research-source/fusion-training-original-{main_19.py,RunModel_19.py,LossFunction.py}`. The original full MAO-B checkpoint is separately recovered and tested. The other 99 locally found DUD-E checkpoints belong to a grid-only network and cannot score the full Fusion path.

The paper reports a 102-target DUD-E evaluation; its aggregate figures must not be ascribed to these particular checkpoints or the browser. The four new checkpoints were trained from the original target files `research_works/MolecularGridFusion/TLDTI_GridSmi/DataSets/DUDE/{target}_vox_19.txt`, using the original model and grid/token functions with a documented training driver in `scripts/train-fusion-target.py`. They are exploratory local models, not a reproduction of all 102 published target models.

## Training provenance and protocol differences

Preparation hashes the source files and target data, builds each ligand grid with the recovered Open Babel code, and stores a sparse lossless FP32 grid cache in `artifacts/fusion-training-transfer/`. The training report in `artifacts/research-source/fusion-{target}/training-report.json` binds source, data, cache and checkpoint SHA-256 hashes, seed, split, selected epoch, and case-level held-out scores. The full PyTorch checkpoints are `valid_best_checkpoint.pth`; the local browser export is `public/research/fusion-{target}/` with a checked manifest and external ONNX weights. EGFR ran on a Colab T4, PARP1 and DPP4 on Alienware GPU, and HIV-1 protease on Colab T4. HKMU supplied the recovered sources and an independently trained PARP1 run for comparison.

Recreating preparation requires the original Python Open Babel/grid dependencies on a compatible machine; the local Windows export environment alone does not provide them. Colab sessions used for this run were stopped after checkpoint retrieval. Kaggle CLI 2.2.4 was installed locally but was not used for compute because Kaggle credentials were unavailable; the four target runs completed on the resources above.

The original training code trains five contiguous development folds, selects by validation accuracy, regenerates a conformer in each batch, drops partial batches, and uses a batch-size-eight PolyLoss expression. The new driver trains **one** of those five folds, selects the best validation average precision, reuses one cached conformer per compound, retains partial batches and corrects PolyLoss to the actual batch size. CUDA uses mixed precision where available. These changes make the run executable and auditable but mean the new checkpoints are not an exact paper training reproduction. The last 20% of each target file is untouched for model selection and used as its designated held-out set; it is still DUD-E distribution data, not a prospective assay.

`scripts/audit-fusion-splits.py` found zero canonical-SMILES overlap between development and test for the four new targets. Bemis–Murcko scaffold overlap remained: EGFR 159/1084 test rows, PARP1 141/1016, DPP4 139/1066 and HIV-1 protease 477/1072. See `artifacts/fusion-split-audit.json`. The same source and decoy construction can still make the classification task easier than real compound discovery. High held-out AUROC or AP here does not establish novel-scaffold, external-library or prospective performance.

The native held-out assessment uses cached original preprocessing grids. `scripts/validate-fusion-target-native.py` compares the selected PyTorch checkpoint and ONNX export on six held-out examples (three actives and three decoys). `scripts/validate-browser-fusion-target.cjs` compares those same input tensors with Chrome ONNX Runtime Web, checks hashes and repeats inference. `scripts/assess-fusion-heldout.cjs` then runs every designated test SMILES through the **actual browser** chemistry, grid, tokens and checkpoint. Case-level success or rejection, grid hash, score and label are saved in `artifacts/browser-fusion-{target}-heldout.json`. The native source-grid and browser-generated-grid assessments have different conformers, so their discrimination measures are reported separately. A rejected row does not receive an imputed score; rejection can remove actives, and the scored-only AUROC/AP cannot represent all submitted compounds.

A separate HKMU PARP1 run used the same source, data/cache hashes, seed and BF16 mode, but selected epoch 14 instead of 18 and measured held-out AUROC 0.99719 / AP 0.98722 rather than 0.99875 / 0.99309. Its report is `artifacts/fusion-training-transfer/parp1-training-report.json`; the local-preview checkpoint is the Alienware run named in the table. Training is not bit reproducible across these GPU runs, so the single selected checkpoint and its hash define the deployed calculation.

Maximum six-case PyTorch/ONNX and native/Chrome absolute score errors were EGFR 3.09e-18 / 2.87e-18, PARP1 6.71e-12 / 2.27e-12, DPP4 5.44e-15 / 5.44e-15 and HIV-1 protease 5.96e-8 / 1.79e-7. Repeated inference on the same grid was bit stable. A repeat of 20 original held-out SMILES per target changed generated grid voxels for 12 EGFR, 13 PARP1, 12 DPP4 and 14 HIV-1 protease successful rows. The largest score change in these probes was 9.11e-6 for PARP1; the other three had no observed score change, often because outputs saturated. Exact conformer repeatability is not established. The production result saves its actual grid and checkpoint hashes. Input rejection is visible rather than silently scored.

Browser preprocessing rejected 142 EGFR, 73 PARP1, 140 DPP4 and 39 HIV-1 protease test inputs. For EGFR, 110 failed stereochemistry preservation, 24 yielded invalid coordinates and 8 exceeded the accepted connected/length contract. The corresponding counts are PARP1 32/34/7, DPP4 115/24/1 and HIV-1 protease 25/11/3. Rejected actives were 2, 4, 19 and 16 respectively. This uneven loss of actives is a material coverage limit; scored-only discrimination must not be interpreted as whole-set performance.

These checks establish source/export/browser numerical fidelity and bounded in-distribution ranking only. On 17 October 2026, the project owner explicitly requested release of all five targets. The four additional manifests now bind their existing six-case native/Chrome parity reports and native/autograd/ONNX Grad-CAM export checks through `validation.referenceSha256`; `validation.status: passed` describes those numerical checks. It does not claim independent activity-set validation, prospective performance, calibration or exact reproduction of the published 102-target study. The coverage and conformer-repeatability limits above remain unchanged.

The original weight bytes are publicly hosted at immutable Hugging Face revision `8438a8c92c5aedd45b98b425aa6614f613fe7088`, with the same SHA-256 values and byte counts. Owner authorization for publication is recorded in `docs/release-approval.json`. The normal worker validation guard and full publication gate remain enabled. Browser scoring and Grad-CAM are checked on the actual public origin before publication is reported complete. Each checkpoint still requires roughly 901 MB downloaded on demand; a visitor does not download all targets just by opening the site.

## Visitor workflow

The Screening controls accept one connected SMILES of at most 100 characters and a checkpoint-backed target. They show model scope, progress, validation errors and cancellation; the result JSON includes target, input, model hashes, grid/token hashes, score and limitations. Different target scores are not directly comparable. The Binding-affinity method stays a separately credited GNINA prepared-pose exercise alongside the central AGIMA-Score research. Its receptor-chain, ligand-identity, bound-pose and coordinate-frame choices and native reference are documented in `docs/custom-input-validation.md`.

Run `npm test`, `npm run check`, `npm run build`, `node scripts/check-custom-ui.cjs` and `node scripts/assess-complex-submission.cjs` locally. For each new target, run `scripts/validate-fusion-target-native.py TARGET` with the project Python environment, then `node scripts/validate-browser-fusion-target.cjs TARGET` and `node scripts/assess-fusion-heldout.cjs TARGET`; reports reside under `artifacts/fusion-target-validation/` and `artifacts/browser-fusion-*-heldout.json`. The local preview is `http://127.0.0.1:4321/protein-ligand-affinity/` via `npm run demo:start`. `node scripts/check-publication.mjs` checks all five target manifests, original figure records and immutable hosting URLs. The September measurements above remain historical measurements; the October publication uses the same checkpoint weights.
